## 复用与决定

| 可复用项／阻碍 | 证据 | 处理决定 |
| --- | --- | --- |
| Java＋XML 原生工程 | app 与标准 AndroidX 依赖；无 NDK、远程音频服务或广告 SDK | 直接导入 app、Gradle 配置和 LICENSE，保持内部 namespace，独立 applicationId |
| 调音处理 | MainActivity → SoundAnalyzeCore → AudioRecord，44100 Hz / 4096 样本 → Envelop（默认）或 YIN 等 → PlayNoteCore 音高换算 → Handler → NeedleView | 保留采集和检测；P2 可替换显示层，无需重写算法 |
| 节拍处理 | MetronomeFragment → PlaybackService / MetronomeCore → AccuracyTimer → PCM AudioTrack；播放标记反馈 UI | 保留引擎；50/60/120 BPM 定时器各运行约一分钟，另做模拟器启停检查 |
| 启动固定空等 | AudioUtils.IsAudioWorking 新建线程却不 start，循环 100×10ms 后无条件视为成功 | 本轮运行时修复：直接检查 AudioTrack.getMinBufferSize 的返回值，去掉无效等待 |
| 跟拍时间基准 | Timer 使用 System.nanoTime 补偿耗时，但音频每拍 pause/flush，部分超时使用墙上时钟，未输出硬件帧时间戳 | 普通节拍可继续验证；现有 UI 回调不能直接充当 P3 评分时刻 |
| 节拍过载和音频抖动风险 | 固定频率调度落后后可能追赶；每拍重启缓冲需要真机确认；周期取整数毫秒 | 本轮不替换引擎；实测异常再定位修复 |
| 录音生命周期风险 | stopFromUi 中断线程后立即释放共享 AudioRecord，未等待线程完全退出 | 模拟器先验基本切页，快速切页与后台恢复列入真机待验；不宣称已排除竞争 |
| 原型安装身份 | 独立包名、versionCode=1、固定开发证书 | 不覆盖原 Diatronome；后续原型版本必须沿用身份递增版本。签名私钥单独保存、不进入公开仓库；CI 输出未签名 APK，维护者本地签名后交付 |
